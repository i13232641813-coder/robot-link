## 1. 这个协议解决什么问题

两块 ESP32，一根 UART 线，一个方向。

- **A 板（发送端 / 视觉侧）**：算出目标在哪，把结果发出去。
- **B 板（接收端 / 执行侧）**：收到、校验、拆出数字，交给上层使用或送 VOFA+ 显示。

协议就是这两块板之间的**唯一约定**。任何一端单方面改动，另一端当天就会解析失败。

---

## 2. 物理层

| 项目 | 约定值 |
|---|---|
| 接口 | UART（TTL 3.3V） |
| 波特率 | **115200** |
| 数据格式 | 8 数据位 / 无校验位 / 1 停止位（8N1） |
| 接线 | A.TX → B.RX，A.RX → B.TX，**GND ↔ GND 必须共地** |
| 方向 | 单向：A 只发，B 只收 |

> 波特率两端必须**完全一致**。不一致的表现是满屏乱码，不是报错。

---

## 3. 帧格式

```
$<f1>,<f2>,<f3>,<f4>,<f5>,<f6>*<XX>\r\n
```

| 位置 | 内容 | 说明 |
|---|---|---|
| `$` | 帧头 | 接收端靠它判断一帧开始 |
| 中间 | 六个字段，逗号分隔 | 十进制 ASCII，**一个字符就是一个字节** |
| `*` | 收尾分隔符 | 之后紧跟两位校验 |
| `<XX>` | 异或校验 | 两位**大写**十六进制 |
| `\r\n` | 行结束符 | 接收端忽略，不参与校验、不算字段 |

**为什么用十进制 ASCII 而不是二进制打包：**

1. 串口助手能直接肉眼看到整帧，调试成本接近零；
2. 字段里只可能出现数字和逗号，**永远不会意外出现 `$` 或 `*`**，所以不会出现"帧里又冒出帧头"的情况。

---

## 4. 字段定义

| # | 名称 | 类型 | 单位 | 取值范围 | 说明 |
|---|---|---|---|---|---|
| 1 | `x` | int16 | mm | -32768 ~ 32767 | 目标横坐标 |
| 2 | `y` | int16 | mm | -32768 ~ 32767 | 目标纵坐标 |
| 3 | `conf` | uint8 | — | 0 ~ 100 | 置信度，百分比整数 |
| 4 | `valid` | uint8 | — | 0 / 1 | 本帧是否包含有效目标 |
| 5 | `ts` | uint32 | ms | 0 ~ 4294967295 | 发送端上电后毫秒时间戳（`millis()`） |
| 6 | `seq` | uint8 | — | 0 ~ 255 | 帧序号，每帧 +1，255 之后回绕到 0 |

**字段顺序一错，数字全错，而且不会报错。** 这是本协议最危险的地方。

---

## 5. 校验

对 `$` 与 `*` **之间**的所有字符逐字节异或（XOR），不含 `$`、`*`、`<XX>`、`\r\n`。

```
xor = 0
for each byte b in payload:
    xor = xor ^ b
checksum = 两位大写十六进制，不足补 0
```

示例：载荷 `473,126,87,1,12345,42`

```
0x34^0x37^0x33^...   →   0x20
```

完整帧：`$473,126,87,1,12345,42*20`

> **校验范围必须两端写死同一句。** 一个算上了 `$`、一个没算，表现是"每帧都校验失败"，而且极难查。

---

## 6. 发送时序

| 项目 | 约定 |
|---|---|
| 发送周期 | **20 ms（50 Hz）** |
| 链路超时 | 接收端连续 **200 ms** 未收到通过校验的帧 → 判定超时 |
| 超时后接收端行为 | 保持上一次数据不动，同时把 `valid` 视为 0，并向上层上报 |

单帧长度约 27 字节，115200 下约 2.3 ms 发完，50 Hz 只占约 12% 带宽，余量充足。

---

## 7. 没有抓到目标时发什么

**照常发帧，不允许停发。** 停发和掉线在接收端看起来一模一样，无法区分。

| 字段 | 取值 |
|---|---|
| `valid` | 0 |
| `conf` | 0 |
| `x` / `y` | 0 |
| `ts` / `seq` | 照常递增 |

---

## 8. 异常处理

| 情况 | 处理 |
|---|---|
| 校验不一致 | 整帧丢弃，**不回复、不回 NAK** |
| 丢帧后 | 接收端继续扫描下一个 `$`，不等待重传 |
| 一个 `$` 之后累计超过 64 字符仍未见到 `*` | 判定为垃圾数据，清空缓冲区，回到"等 `$`"状态 |
| 坏帧计数 | 接收端维护 `bad_frame_count`，仅用于排障，不上报 |
